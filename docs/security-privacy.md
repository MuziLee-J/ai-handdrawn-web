# 安全、隐私与合规说明

> 本文档描述当前实现与待办，不构成法律意见，也不代表已经满足任何司法辖区的合规要求。

---

## 1. 数据清单

| 数据 | 位置 | 用途 | 默认保留 |
|---|---|---|---|
| 上传照片/裁剪副本 | `$DATA_DIR/files/uploads` + `assets` 表 | AI 转换输入 | 清理脚本按未引用 7 天/软删除 30 天处理 |
| 生成图片 | `$DATA_DIR/files/generated` + `assets` 表 | 结果展示/排版 | 被任务或作品引用时保留 |
| 任务记录 | `tasks` 表 | 状态、模型、提示词版本、费用 | 成功任务长期保留；失败/取消 30 天后清理 |
| 排版文档 | `works.doc_json` | 再次编辑 | 长期保留，除非用户删除 |
| 会话 Cookie | 浏览器 + `sessions` 表 | 匿名身份 | 30 天 |
| 额度计数 | `usage` / `global_usage` | 成本控制 | 按日 |
| 导出图片 | 用户设备下载 | 成品 | 不在服务器保存 |

当前没有账号、手机号、邮箱、支付信息。

## 2. 密钥管理

- `ARK_API_KEY` 只在 Node 服务端通过 `process.env` 读取。
- 浏览器代码、客户端组件、API 响应、日志均不包含 Key。
- `.env.local` 在 `.gitignore` 中；`.env.example` 不含真实值。
- 生产使用平台 Secret/环境变量，不要写进 Dockerfile。
- 如果 Key 泄露：
  1. 立即在火山方舟控制台禁用/轮换；
  2. 检查账单与异常任务；
  3. 重启服务；
  4. 不要只删除代码中的字符串。

---

## 3. 访问控制

- 每个浏览器获得随机 UUID 会话，写入 `HttpOnly; SameSite=Lax` Cookie。
- 资产、任务、作品查询都带 `session_id` 条件。
- `/api/files/[id]` 只允许当前会话读取；无 Cookie 或跨会话返回 404。
- 文件路径不暴露给客户端；存储键由服务端生成。
- 文件不以永久公开 URL 暴露。
- 删除作品为软删除；实际文件由清理脚本按策略删除。

### 限制

- 没有账号体系，无法跨设备恢复；清除 Cookie 等于失去访问权。
- 如果 Cookie 被同一设备上的其他人获取，可能访问该会话作品；当前没有二次验证。
- 多实例部署时，会话/额度/限流需要迁移到共享存储。

## 4. 上传与内容安全

已实现：

- 文件大小、像素、宽高限制；
- magic bytes 校验，拒绝伪装扩展名；
- 仅 JPEG/PNG/WebP；
- 图片解码失败拒绝；
- 上传限流 20 次/分钟/会话；
- 生成限流 6 次/分钟/会话；
- 任务幂等，防重复付费。

未实现：

- 上传前的图片内容审核；
- 敏感内容检测/关键词过滤；
- 人工复核与申诉流程；
- 未成年人保护策略；
- 病毒扫描。

当前依赖火山方舟的内容审核，并将错误映射为 `CONTENT_BLOCKED`。公开上线前必须补充适合业务的内容安全方案。

---

## 5. 第三方 AI 数据处理

使用火山方舟 Seedream 4.0 时：

- 服务端会把**原图 Base64** 和提示词发送给火山方舟 API。
- 生成结果由火山方舟返回 URL，服务端立即下载到本机。
- 供应商可能按其条款记录请求、用于安全审核或服务改进；具体以火山方舟最新隐私/数据处理条款为准。
- 当前没有把用户照片用于训练。
- 当前没有把作品默认公开。
- 当前没有把图片发送给火山以外的第三方。

上线前必须核实并写明：

1. 数据存储地域；
2. 保留期限；
3. 是否用于模型训练；
4. 商业使用与内容政策；
5. 跨境传输情况（如有）；
6. 用户如何撤回同意/删除数据。

## 6. 日志与监控

当前服务端日志：

- 记录 API 路径、HTTP 状态、错误名称/消息；
- 不记录 `ARK_API_KEY`；
- 不记录完整请求体或 Base64 图片；
- 不记录完整 Cookie。

生产建议：

- 配置日志脱敏；
- 限制日志保留期限；
- 监控失败率、额度、磁盘；
- 不把用户图片写入日志/APM。

---

## 7. 用户权利与删除

当前可执行：

- 在作品集删除作品（软删除，列表/详情立即不可见）；
- 清除浏览器 Cookie 放弃会话；
- 管理员运行 `npm run cleanup:apply` 清理过期数据。

当前不足：

- 没有“一键删除我的全部数据”入口；
- 没有数据导出；
- 没有账号注销；
- 软删除后文件不会立即物理删除。

公开服务前建议增加：

- 用户数据删除入口；
- 删除确认与状态反馈；
- 保留期限说明；
- 数据导出（如适用）。

---

## 8. AI 生成内容标识

- 结果页会显示供应商/模型/是否 mock。
- mock 模式明确标注“不是 AI 生成结果”。
- 导出图片当前**没有**自动添加“AI 生成”水印/元数据。
- 公开上线前，根据适用法规评估是否需要在图片或界面添加 AI 生成标识。
- 不得把 mock 演示图作为真实 AI 能力宣传。

## 10. 安全事件响应（建议）

1. 立即隔离受影响服务/密钥；
2. 轮换 `ARK_API_KEY` 与会话密钥（如后续引入）；
3. 保留必要日志，避免扩散用户图片；
4. 评估影响范围（任务、作品、账单）；
5. 按适用法律/平台要求通知用户与监管；
6. 修复后复盘并补充测试。
